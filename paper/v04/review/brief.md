## What to look for (examples found in a first scan; search for more)

1. **Process narrative that belongs in a lab notebook, not a paper.** Sentences such as "the pass counts include
   fresh-session reruns after two integration defects were corrected and after the accepted-wording lists of two tasks
   were extended on inspection of the responses", "under the final scoring rules after integration fixes and
   wording-rule revisions" (also in the Table 2 caption and the abstract), "the other three models were run after these
   changes", "wording-rule changes after response inspection limit interpretation". Decide what a reader needs: either
   one neutral sentence in the benchmark design (scoring rules were fixed before the final runs; any earlier
   iteration is not a result) or nothing. Do not keep the same disclosure in three places.
2. **Instruction echoes.** Passages that restate rules given to the system or to the team as if they were findings,
   e.g. "The agent is required to report the defaults used", "Transcript wording was otherwise retained", "The internal
   package name was replaced by the system name where it appeared in the responses", "The cycle-time plot was
   regenerated by executing the recorded tool call with the same arguments and English labels", "checked by the
   author". Keep only what a reader needs to interpret the evidence (for instance, that the transcripts are verbatim
   outputs of the system) and phrase it as method, not as a note to the editor.
3. **Tooling and environment detail that is not part of the method**: command-line interface version numbers,
   "MCP server startup on each turn", "fresh sessions" with "separate storage", "recorded response digest", "4000
   characters", session memory implementation details, file formats of reports (markdown and spreadsheet), file
   links in answers, "the released evaluation package", "the harness". Keep what defines the experiment (one run per
   model, isolated sessions, what wall time includes) in one sentence each; drop the rest.
4. **Caption disclosure text.** Each schematic caption carries a long AI-assistance sentence. Elsevier requires the
   disclosure, but it can be one short clause per caption (e.g. "Schematic drawn with AI assistance, see the
   declaration") with the full statement once in the declaration section. Shorten accordingly.
5. **Anything else that only the authors would understand**: internal tool names used as prose nouns where a plain
   description would do (keep tool names in typewriter font where the tool itself is the subject), "label-based"
   phrasing, references to how figures or tables were produced, mentions of specific people, machines or accounts.
6. Re-check the three sections written most recently (LLM models and access; Benchmark results; Discussion
   paragraph on model differences) for the same problems, and for any claim not supported by Tables 2 and 3.
7. Apply the house style in `review/ccr-style-SKILL.md` to every sentence you keep or write.
